# Sora для Android и Linux

Общий клиент находится в разработке и не опубликован как релиз. Один модуль отвечает за интерфейс, подписки, импорт, задержку и сохранение состояния; платформенные модули отвечают только за сеть и системную интеграцию.

## Что уже работает

- HTTPS-импорт через libXray: VMess, VLESS, Trojan, Shadowsocks, SOCKS и Xray JSON;
- отдельные сворачиваемые подписки, защита от дублей, переименование, удаление и автообновление;
- `profile-title`, `subscription-userinfo`, описание с Markdown и квота подписки;
- выбор сервера, флаги с нейтральной планетой, поиск и настоящий `pingBatch` без выдуманных значений;
- сохранение выбранного режима и сервера;
- Android `VpnService` для TUN и foreground-служба для локального прокси;
- Linux SOCKS/HTTP, системный прокси GNOME/KDE с резервной копией и TUN при запуске с необходимыми правами;
- монохромный адаптивный интерфейс без Material-компонентов из коробки.

## Проверка

```text
gradlew.bat :shared:jvmTest :desktopApp:compileKotlin
```

Android требует установленный Android SDK 37. Linux `deb` собирается только в Linux:

```sh
./gradlew :shared:jvmTest :androidApp:assembleDebug :desktopApp:packageDeb
```

Сборка загружает закреплённые артефакты libXray v26.7.28 и проверяет их SHA-256 до распаковки. GitHub Actions сохраняет APK и `deb` только как временные тестовые артефакты — тег и GitHub Release не создаются.

## Хранение и сеть

- Android хранит состояние в приватных `SharedPreferences`; конфигурация службы остаётся недоступной другим приложениям.
- Linux пишет состояние атомарно в `$XDG_CONFIG_HOME/sora/state.json` и резервную копию прокси в `$XDG_STATE_HOME/sora/proxy.properties`.
- Ссылки подписок и конфигурации не попадают в пользовательский журнал.
- Android TUN запрашивает системное разрешение. Linux TUN не маскируется под рабочий без прав: пункт отключён.
