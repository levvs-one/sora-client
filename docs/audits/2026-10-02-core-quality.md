# Аудит качества кода ядра

Дата: **02.10.2026**. Область: `core/errs`, `core/secret`, `core/session`,
`core/.golangci.yml`. Метод: чтение кода, прогон линтера с конфигурацией репозитория,
прогон тестов, кросс-сборка.

## Что считается качеством в этом репозитории

1. Документация на экспортируемом символе объясняет не «что это», а «почему так».
2. Ошибка — это значение в каталоге, а не строка; строка живёт в интерфейсе.
3. Комментарий, который объясняет очевидное, удаляется; комментарий, который
   объясняет решение, остаётся навсегда.
4. Нет функции без причины существовать. Нет структуры без владельца.
5. Мёртвый код — дефект, а не наследие.

## Устранено в этом цикле

| № | Находка | Что сделано |
| --- | --- | --- |
| 1 | `DefaultKey` перебирал весь каталог на каждый вызов | Отсортированный список ключей строится один раз при инициализации |
| 2 | Сессия брала блокировку дважды на пути `SetKillSwitch` | Появилась `settingsLocked`; блокировка берётся ровно один раз |
| 3 | Сессия подписывалась на события движка уже после `Apply` | Подписка перенесена до возврата из `Start` |
| 4 | Тест сравнивал ошибки через `!=` | `errors.Is`, как требует `errorlint` |
| 5 | Имена ключей каталога не соответствовали правилу `revive` | `KeyApiVersionMismatch` → `KeyAPIVersionMismatch` |
| 6 | `writeFileAtomic` принимал режим и не использовал его | Режим передаётся в `hardenFile`, то есть аргумент влияет на результат |
| 7 | `G103` и правила путей в тестах были помечены в коде или молча игнорировались | Исключения описаны в `.golangci.yml` с объяснением, тесты проверяют сами осмысленные вещи |
