# Центр логов и центр соединений

Дата проверки кода: **06.10.2026**, ветка `feat/core-engines-unified`.

## 1. Что это

Центр логов — одна запись того, что сказали служба Sora и каждое ядро. Интерфейс
её листает, фильтрует, ищет, смотрит вживую и выгружает. Центр соединений — живой
список соединений сессии: куда идёт, каким правилом, через какую цепочку групп и
сервер, сколько трафика. Любое соединение можно закрыть.

## 2. Где живут логи

Только в памяти процесса ядра. Лог туннеля — это список мест, где бывал человек, и
серверов, которыми он пользуется. Файл с ним пережил бы сессию, удаление программы
и проверку устройства. Поэтому на диск ядро логи не пишет; наружу они уходят только
явной выгрузкой, и файл сохраняет интерфейс туда, куда скажет пользователь.

Запись ограничена числом записей (по умолчанию 20 000) и байтами (8 МиБ). Старые
записи уходят первыми, счётчик вытесненных виден в статистике. Сообщение длиннее
4 КиБ обрезается. Клиент не может поднять пределы выше 200 000 записей и 64 МиБ.

## 3. Как туда попадают записи

* **Ядра.** Вывод каждого ядра режется на строки и разбирается в его собственном
  формате: logfmt у mihomo, `LEVEL[секунды]` у sing-box, `дата [Level]` у Xray.
  Разборщики проверены на настоящем выводе mihomo 1.19.32, sing-box 1.14.2 и
  Xray 26.3.27. Строка, которую разборщик не узнал, сохраняется как есть с уровнем
  info. Строки access-лога Xray уровня не имеют и считаются debug.
* **Служба.** `slog`-обработчик пишет записи службы в центр с источником `core`, а
  обычный журнал службы продолжает писаться туда же, куда раньше.

## 4. Маскирование

* Учётные данные (UUID, пароли, ключи, ссылки подписок) и адреса серверов плана
  маскирует супервизор ядра, до того как строка попадает в центр. Сквозной тест
  пропускает трафик через каждое ядро и проверяет, что UUID и пароль не встречаются
  ни в одной записи.
* Адреса сайтов, которые посещает человек, по умолчанию заменяются на
  `[destination]`: имена хостов, IPv4 и IPv6 с портами. Время вида `15:02:43` и
  теги ядра не трогаются. Записывать адреса можно включить в настройках
  (`record_destinations`) для отладки.

## 5. Уровень записи меняется без переподключения

Ядра всегда работают на уровне debug, а центр отбрасывает всё, что ниже выбранного
уровня, до сохранения. Поэтому смена уровня действует сразу, на всех трёх ядрах, без
перезапуска, который оборвал бы соединения. Отброшенные строки нигде не хранятся.

## 6. Работа с записью

| Возможность | Как |
| --- | --- |
| Фильтр | минимальный уровень, источники, подстрока без учёта регистра, регулярное выражение RE2 до 512 байт (работает за линейное время), интервал времени |
| Листание | страницы до 1000 записей, от новых к старым, курсор `before_sequence` |
| Живой просмотр | `WatchLogs`: сначала записи после курсора, потом новые. Отставший клиент получает RESOURCE_EXHAUSTED и продолжает с последнего номера, а ядра не тормозятся |
| Повторы | одинаковые подряд сообщения в пределах 30 с сворачиваются в одну запись со счётчиком; живой клиент получает её повторно с тем же номером |
| Статистика | количество по уровням и источникам, объём, предел, вытесненные — по всей записи, а не только по фильтру |
| Выгрузка | текст, JSON Lines, CSV, с тем же фильтром. В CSV ячейка, похожая на формулу, получает апостроф, чтобы таблица не выполнила текст из лога |
| Очистка | номера записей продолжают расти, курсор клиента не путается |

## 7. Доступ

Каждый метод центра логов и центра соединений требует токен управления, как
Connect. Транспорт ядра уже закрыт от других машин и других пользователей, а токен
отсекает остальные процессы того же пользователя. Ограничение, которое надо знать:
файл токена читается этой учётной записью, поэтому процесс, запущенный от того же
пользователя и знающий, где лежит файл, может его прочитать. На Android у каждого
приложения своя учётная запись, и там этого ограничения нет.

## 8. Центр соединений

mihomo и sing-box отдают соединения через Clash API (`GET /connections`,
`DELETE /connections/{id}`); формат ответов проверен на обоих. У Xray такого API нет,
поэтому для сессии на Xray центр соединений отвечает
`core.connections.unavailable`, а счётчики трафика остаются общими.
