# Аудит поверхности управления

Дата: **02.10.2026**. Область: `proto/sora/core/v1`, `core/control`. Метод: чтение
контракта и реализации методов, прогон тестов, сборка под все платформы.

Control plane — единственная точка, где недоверенный клиент говорит с
привилегированным процессом. Поэтому аудит именно поверхности: что клиент может
попросить, чем он за это платит и что происходит при злоупотреблении.

## Что может клиент

| Метод | Что делает | Чем защищён |
| --- | --- | --- |
| `Handshake` | отдаёт версию контракта и возможности | ничего не меняет, аутентификатор не нужен |
| `Connect` | поднимает сессию по плану | версия, токен, лимиты, валидация плана |
| `Disconnect` | останавливает сессию | версия, токен, сверка идентификатора сессии |
| `GetStatus`, `GetStats` | читают состояние и счётчики | версия |
| `WatchEvents` | поток событий с воспроизведением | версия, сверка сессии |
| `ParseImport`, `FetchSubscription` | разбор и загрузка подписки | версия, лимиты, детект формата |
| `ProbeServers` | измерение серверов | версия, лимит числа точек |
| `RunDiagnostics`, `ExportDiagnostics` | отчёт и архив | версия, маскирование |
| `SetKillSwitch` | включение и выключение блокировки | версия, сверка сессии |
| `PutSecret`, `DeleteSecret` | хранение учётных данных | версия, валидация ссылки |

## Свойства, которые держит реализация

1. **Проверки в фиксированном порядке.** Версия, токен, лимиты, форма запроса.
   Запрос, не прошедший одну из них, не коснулся системы.
2. **Материал проходит ровно через один метод.** Тест по дескриптору службы
   падает, если второй метод ever получит поле с секретом.
3. **Сессию нельзя остановить чужой.** `Disconnect` и `SetKillSwitch` сверяют
   идентификатор сессии с работающей и отвечают `NOT_FOUND`, а не останавливают
   что бы то ни было.
4. **Ошибки не выбирают путь.** Доменные ошибки приходят в поле ответа, ошибки
   соединения — статусом транспорта. У клиента один путь на каждый случай.
5. **Деталь ошибки замаскирована.** Маскировщик получает секреты и идентификаторы
   плана, поэтому ни один ответ не называет ни пароль, ни провайдера.

## Находки и решения

| № | Что рассмотрено | Решение |
| --- | --- | --- |
| 1 | Может ли клиент прочитать чужой секрет | Нет: методов чтения нет вовсе, `PutSecret` только пишет под указанной ссылкой, а материал читает только ядро при применении плана |
| 2 | Не может ли клиент занять чужую сессию | Идентификатор сессии проверяется на `Disconnect` и `SetKillSwitch`; чужой даёт `NOT_FOUND` |
| 3 | Не может ли клиент исчерпать память ядра большим планом | План ограничен 4 МиБ и 5000 outbound, правило проверяется до любых выделений |
| 4 | Не может ли клиент завалить ядро потоком probe-запросов | Не более 256 точек на запрос, параллельность 8, поток закрывается при отмене |
| 5 | Не может ли клиент заставить ядро писать на диск по произвольному пути | Пути всех файлов ядра заданы константами, клиент не передаёт ни одного пути |
| 6 | Не может ли клиент увидеть чужой журнал событий | `WatchEvents` сверяет идентификатор сессии |
| 7 | Не может ли клиент заставить ядро долго удерживать соединение | У каждого метода своя граница времени, если клиент её не задал |
| 8 | Не ломается ли контракт при расширении | Добавления только вперёд; `buf breaking` с уровнем FILE проверяет каждое слияние |

## Проверки, которые прошли

* Тесты control plane: handshake, отказ по токену, отказ по версии, запуск с
  разрешением секрета, три вида отказа в плане, защита чужой сессии, статистика
  без сессии, импорт без утечки учётных данных, жизненный цикл секрета, отказ
  ссылке-пути.
* Тест контракта: материал проходит только через `PutSecret`, коды ошибок
  уникальны и префиксованы.
* `golangci-lint`, `go vet`, `gofmt`, кросс-сборка шести целей.
